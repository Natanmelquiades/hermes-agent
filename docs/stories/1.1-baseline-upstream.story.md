# Story 1.1 — Baseline técnico e coordenação upstream

## User Story

Como responsável pela contribuição do Hermes Desktop,
quero validar a `main` atual e definir uma estratégia única para as PRs pt-BR existentes,
para que a implementação comece sobre uma fonte de verdade atualizada e sem duplicação upstream.

## Contexto

O repositório oficial é `NousResearch/hermes-agent`. A PR #86292 contém uma tentativa de pt-BR, mas a análise anterior registrou que ela está divergente e desatualizada em relação à `main`. A implementação não pode copiar seu catálogo sem reconciliação.

## Acceptance Criteria

1. O commit exato da `main` usada na implementação está registrado.
2. `npm ci` e os gates relevantes do Desktop têm resultado registrado no baseline.
3. Falhas preexistentes ou dependentes do locale do host estão separadas de falhas introduzidas pelo candidato.
4. A estratégia entre issue #40239 e PRs pt-BR existentes está documentada localmente.
5. Nenhuma issue, comentário, PR, push ou merge remoto é realizado nesta story.

## Tasks / Subtasks

- [ ] Confirmar `git status`, remote e commit da `main`.
- [ ] Ler `AGENTS.md`, `apps/desktop/AGENTS.md`, `apps/desktop/DESIGN.md` e `apps/desktop/package.json`.
- [ ] Instalar dependências conforme o lockfile, sem executar scripts upstream desconhecidos fora do fluxo normal do projeto.
- [ ] Executar `npm run typecheck`, `npm run lint`, `npm run test:ui` e `npm run test:desktop:platforms` no baseline quando possível.
- [ ] Registrar resultados em `docs/qa/baseline-1.1.md`.
- [ ] Registrar decisão de coordenação em `docs/qa/upstream-coordination-1.1.md`.
